## Planned ownership gates

First repair 24-slot VCON coverage and current native-shell query/TASKS collection; do not change SJ_MAX, sessions, channels, child records or application formats. The native shell is QDOS/386's current system interface and its query capacity is explicitly within R4 scope; third-party/historical application sources and original accepted disks remain unchanged. Existing installed shell binaries cannot acquire larger buffers from a kernel update alone; deliver a separately built R4 shell on a new derivative test disk, retain originals.

Then introduce guarded compile-time controls (defaults24/8/20) and audit all changed dependent extents, bitmap shifts and per-CPU initialization. Reject unsupported32 CPU/256job configurations rather than implying qualification. 64 is a separate opt-in candidate only after bitmap conversion and runtime proof. No public ABI, device policy or independent quota change is required for24/64. If proof fails, retain validated 24 and report64 incomplete.

Testing must observe every job slot, reserved slots included; high-slot session/channel ownership and visible TASKS/PS/KILL; exhaustion/stale/tag-wrap/invalid IDs and CPU pins; parent-child rollback/reaping; default normal applications/GCC/cache; bitmaps and exact quiescent heap/frame/session/surface/handle recovery. Test-only instrumentation may create lightweight held kernel jobs to exercise allocator coverage without pretending all slots are available as protected user processes.


## Ownership follow-up after the audit checkpoint

The raw baseline inventory includes the cache's second job-bit domain: source/kernel/r20w.c:68,94,156,183,195,199,219,613,637,664,777,827,947,1017. Each24-byte entry's rmask was one unsigned32-bit reader-reservation word; reserve/compact/release, eviction, completion/invalidation/reset and diagnostic bit counting consume it. The original #error correctly blocks JOB_MAX>32 independently of jobs.c dead_mask. This was the first64 build counterexample. R4's experimental 64 adds a separate high word and updates every consumer/clear, retaining the same BKL and generation rules. Stopped-guest evidence observes high bits with zero low-word bits when only high-slot readers run. Default 24 retains entry stride24 and byte-identical B3 images. The64 injected-accounting failure still blocks acceptance.

The current accepted resource header centralizes job/CPU/session defaults; native v1/v2 buffers consume it, VCON job tables use JOB_MAX, per-CPU arrays/TSS/initialization follow KX_NCPU, and the internal deferred-death bitmap uses bounded32-bit words. None of the independent history/child/channel/surface/cache-policy bounds is unified by coincidence. Full profile/test status and remaining client/representation limits are in R4-CONFIGURATION, R4-ABI-REVIEW and R4-KNOWN-LIMITATIONS.
