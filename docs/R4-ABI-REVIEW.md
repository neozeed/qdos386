# R4 application and resource ABI review

Accepted baseline is R3 r3-gate4-accepted at 3900b200ca182c445db0ba3d64c28beadc7bed02. R4 keeps trap numbers, int0x30 EAX/EBX/ECX/EDX convention, saved register/privilege frames, record versions and byte layouts, a.out/protection flags, loader origins, error codes and tagged handles unchanged. The SDK and historical applications/toolchains are not edited. Only two current native-shell includes change query-buffer capacity; historical shell recipes retain their original limits and executable behavior.

The seven R3 layout probes compile into the identical object SHA-256 `0dd58c65ee9f7469322988e6b1071aa0e0377d01ecd839e87873fd34f1e8529d` under default R4 flags. This includes struct job=204 bytes and the recorded VAS/frame/image/surface/heap-header sizes; it is targeted layout evidence, not a proof of every possible caller. Existing native GCC, original R16T faults/register tests, Bounce, Elite/Hack and original cache helpers provide actual runtime compatibility evidence.

| Representation | Review and outcome |
|---|---|
| Job IDs | Same positive `(tag<<16)|slot`, sixteen-bit slot component and generation1..0x7ffe; allocator scans from1, SYSTEM remains0. Full ID validated. Test-only boot hook forces the wrap boundary and restores original tags before normal boot. Finite generation wrap can eventually alias an ancient ID; R4 does not invent perpetual stale-ID protection |
| Job query v1/v2 | Header16 and record40/128 bytes; caller chooses extent, v1 excludes SYSTEM, v2 includes it. Slot remains one byte. All slots0..23 visible through raw v2 and current TASKS, all 1..23 through v1/PS. Candidate64 also demonstrates0..63, with reserved test holders explicitly counted |
| Capability words | Default job maximum still24. Candidate64 fits existing eight-bit table-size field. 256 would overlap adjacent/version bits and is rejected rather than silently re-encoded |
| CPU controls | AUTO8 sentinel stays8; signed-char affinity/owner fields, fixed INFO/STATS/TOPO payloads remain. C arrays/TSS use configured1/4/8 extents; one-context INFO skips second-CPU reads. CPU 32 collides with existing assumptions/sentinel/payloads and is rejected; no ABI migration is claimed |
| Console/session/channel | Job-indexed ownership expands to actual JOB_MAX; session handles/generations, four static consoles, default 20 sessions and sixteen global channels stay independent. CON channels opened in a child bind to its inherited session; general fd inheritance is not newly promised |
| Shell | Current-shell build uses the same QDOS_CFG_MAX_JOBS for v1 collection and TASKS v2. SJ_MAX remains16. Old linked shell binaries retain their old buffers; kernel update alone cannot enlarge them. Original accepted disk is preserved; derivative disk backs up old shells at /R3 |
| SDK clients | qd_job_list/find still have an internal eight-record cap in the preserved SDK. Raw query ABI is complete and current shell uses it directly. This client-library limitation remains documented, not silently treated as a kernel bound |
| Cache ownership | Default 24 keeps the original24-byte entry and one-word reservation mask, producing identical B3 default images. Experimental64 adds a high ownership word at offset24, stride28; all transitions remain under the same BKL and budget includes actual metadata. This internal layout is not a public ABI. Its strict injected-accounting failure prevents64 acceptance |

No production kernel-buffer exception is added. Legacy diagnostic bridge remains QDOS_LEGACY_DIAGNOSTIC-only. QDOS_R4_TEST_FILL enables a separately built boot test before APs/processes, with no new syscall; default images contain no such hook. The31 low-slot holders in the 64 coverage test are privileged test-only jobs, not claims that64 protected applications fit simultaneously. Raw mapping probes verify supervisor cache pages and process frame ownership.

Actual invalid slot/stale ID, wrong query version/size, out-of-range CPU pin, per-parent child exhaustion, non-child kill/wait, forced environment-copy rollback, high-slot exit/kill/channel cleanup and CPL3 #GP/#PF/refused pointer paths are tested. No ABI-visible representation change needs a compatibility proposal for the accepted24 profile. Future32 CPU/256job work does require one.
