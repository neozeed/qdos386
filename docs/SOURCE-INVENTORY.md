# Inventory scope and evidence

> Preserved R3 baseline document. For current R4 resource changes and profile status, see [R4 configuration](R4-CONFIGURATION.md), [ABI review](R4-ABI-REVIEW.md) and [known limitations](R4-KNOWN-LIMITATIONS.md). The R3 text below is retained for provenance.

SOURCE-INVENTORY.csv covers all C, header, assembly, linker and Python files under source/kernel, source/platform and source/diagnostics/legacy, plus both active Makefiles and source/mk/current.mk: 149 rows. It is a kernel maintenance inventory, not an application export/exclusion list. The broader historical repository inventory remains in reports/r1/R1-ECOSYSTEM.csv. Existing historical applications, SDKs, binaries, assets and reference material remain available and unchanged.

`tests/host/r3/inventory-canonical.py BUILD BUILD_LOG OUTPUT` regenerates the table from the captured forced build and actual a.out object symbol tables. Build is an extracted repository root. Composition names are exact object directories. Exported global symbols and their same-profile object importers are measured; they are not a complete runtime callback/call graph. Header callers are direct textual include mentions and may include inactive paths. Nonlinked entries are retained historical/helper inputs, not assumed dead code. Purpose labels are module-level descriptions; consult the path, exports and contract document for precise operations.

Introduction is the oldest commit returned by git log --follow for that path, explicitly the first tracked repository history, not original authorship. Unestablished original ownership and functional history are UNKNOWN. Verified R2 page-cache and R3 composition functional changes are identified; the five selected cleanup groups, explicit Make configuration and prior relocation are identified as source-only changes. This distinction avoids interpreting a recent comment/move as a new functional implementation. Files that have not had their functional provenance audited remain UNKNOWN rather than inheriting a guessed release number.

The build log and compile-configurations.json preserve flags and ordered linking. Ledger evidence identifies commits and semantic proofs. Earlier inventory assumptions about main/test linkage apply to the previous phase and remain as historical records; they do not override the explicit current compositions.
