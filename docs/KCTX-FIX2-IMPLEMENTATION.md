# KCTX-FIX2 — implementation: exact-ESP resume as the normal kernel path

Base: frozen R14A `7be7353`. The KCTX-FIX1 correction (`docs/KCTX-FIX1-AUDIT.md`) is no longer an opt-in build: it
is the source default and the default build. The audit behind each decision is `docs/KCTX-FIX2-AUDIT.md`.

## 1. The convention (unchanged from KCTX-FIX1, now the only one for current kernels)

Every kernel entry that can switch or resume a job (IRQ0, the service trap, exceptions, the #DF kill path, the
cooperative yield) pushes the interrupted state on the job's stack, calls a C function with that stack pointer and
jumps to `resume_dispatch` with the C function's return value in EAX.

* C side (`kernel/jobs.h`): `KX_RESUME(sp, fmt)` stores `fmt` (0 = cooperative frame, 1 = interrupt frame) in the
  kernel variable `kx_resume_fmt` and returns `sp` **unchanged**.
* Assembly (`kernel/kctx.s`): `resume_dispatch: movl %eax,%esp; cmpl $0,_kx_resume_fmt; je resume_ctx; popal; iret`.

No bit of the stack pointer carries the format, so ESP at any residue mod 4 is resumed exactly. Nothing is rounded,
nothing is rejected, applications are not asked to align ESP. Why one global is safe on this single-CPU kernel
(IF is clear from the write to the read on every path; faults in that window halt) is `KCTX-FIX2-AUDIT.md` §4.

## 3. Why the build cannot mix the two conventions

`PCKCTX = $(if $(filter %/kctx.o,$(PCCTX)),,-DQDOS_KCTX_PTRBITS)` is added to every PC compile rule (and to the
`.pcflags` stamp, so switching rebuilds). The C half therefore follows the linked context object:

* links `kernel/kctx.s` → default C (exact SP);
* links anything else (`context.s`, `paging.s`, `kernel/frozen/kctx-r12a-r14.s`) → historical C.

A mismatch is also loud by construction: the current `kctx.s` references `_kx_resume_fmt`, which only the default C
defines, so current assembly with historical C does not link; historical assembly with current C would lose the format
bit on the first trap of the boot and crash before the shell, so it cannot pass any smoke test.
`tools/kctx2-resume-check.py` reads which convention a linked kernel really contains from its bytes.

| Target | Images | Convention |
| --- | --- | --- |
| `make` / `make all` / `make qdos386-pc` | `build/qdos386/pc-vga/qdos386-vga.img` (QEMU), `build/qdos386/pc/qdos386.img` (Tiny386) | exact |

| `make kfix1-pc` (historical alias) | `build/kfix1/…/kfix1-vga.img`, `kfix1.img` | exact |
| `make r12a-pc` … `r14-pc`, `r13b-epoch*` | the frozen R12A…R14 images | historical (frozen copy) |
| `make pc`, `i386vm`, R7…R12 targets | the frozen R6…R12 images | historical (`context.s` / `paging.s`) |

The current kernel's feature set is exactly R14's (`QDOS386_OPTS = $(R14_OPTS)`): the context fix is the only
functional change in this release. Consequently its bytes equal the independently verified KCTX-FIX1 kernels:
`qdos386-vga.img` = `kfix1-vga.img` = `f8e5d5e1…`, `qdos386.img` = `kfix1.img` = `7c675978…`. The images are named for
the line, not for the release; a kernel banner change was deliberately not made (it would be an unrelated change).

## 6. Not changed

No GW-BASIC change, no application alignment rule, no QDOS API change, still ring 0, still one CPU. `context.s` and
`paging.s` keep their decode (frozen lines only). KCTX-FIX1's own files (`tests/kctx`, `docs/KCTX-FIX1-*`,
`logs/kctx`) are kept as the reference evidence.
