# R11L: the toolchain port

Everything below is **host build** unless stated: the four guest tools are produced on the build machine (bootstrap), and
then only ever *executed* inside QDOS/386 in the self-hosting demonstration.

## Sources and provenance

The sources are the user's legacy tree (`$QDOS386_TOOLS`): `gcc-1.40`, `gas-1.38`, `binutils-1.94`, `bison-1.16`
(GPL, FSF copyright notices kept in the files). `tools/r11l-stage-src.sh` copies them to `build/r11l/src`, converting
CR LF to LF in text files only (GCC 1.40's cpp treats CR as garbage), and records the SHA-256 of every **original** file in
`build/r11l/src/ORIGINAL.SHA256` (820 files: gcc-1.40 289, gas-1.38 73, binutils-1.94 401, bison-1.16 57). The only
guest-specific edits to the legacy sources are in `port/patches/gcc-1.40.patch` (regenerated by `tools/r11l-mkpatch.sh`):

1. `expr.c`: the legacy tree carried a misplaced parenthesis in the `move_by_pieces (gen_rtx (MEM, BLKmode, gen_push_operand ()), ...)`
   call (marked by its author "Is this a typo?"). Passing a small struct by value crashed cc1. The original GCC 1.40 call was restored.
2. `host64.h`: the legacy Linux LP64 host description is replaced by QDOS/386's ILP32 one (`HOST_BITS_PER_LONG 32`,
   `HOST_POINTER_UINT unsigned int`). The target description is unchanged (`tm-i386gas.h`).

GAS and ld needed no source edits: the port is `port/include/*` (the headers the 1980s sources expect - `sys/stat.h`,
`sys/types.h`, `fcntl.h`, `unistd.h`, `malloc.h`, `varargs.h`...) and `port/ld/sysdep.h`.

No tool was replaced by a modern one. Historical options only: `cccp -nostdinc -undef -Di386 -D__i386__`, `cc1 -quiet [-O]`,
`as -o`, `ld -N -T SLOT1.LD -e _start`.

## How the guest tools were built (and by what)

`tools/r11l-cc` compiles each guest source with the **historical stages themselves** (cccp, then cc1, then as):

* cccp and as are the user's x86-64 builds of the historical tools (`$QDOS386_TOOLS/bin`);
* cc1 is the same GCC 1.40 compiler built for the host with the LP64 repairs of the legacy tree and the `expr.c` fix
  (`build/r11l/host-cc1/cc1`);
* the code generator tables (`insn-*.c`, `c-tab.c`, `cexp.c`...) come from the host bootstrap (`scripts/r11l-bootstrap-gen.sh`,
  GCC's own `gen*` programs and bison 1.16).

Scripts: `r11l-try-gas.sh`, `r11l-try-gcc.sh`, `r11l-try-ld.sh` (compile every source, report failures), then
`r11l-link-tools.sh` (link `AS/CCCP/CC1/LD.AOU` with `i386-ld` against `libm/libc/libgcc-qd/libqdos`),
`r11l-build-all.sh` (libraries, guest utilities, tools, MEMSTAT builds, kernels).
So the guest GCC 1.40 binaries were themselves compiled by GCC 1.40 (a host-run copy), not by a modern compiler.

## SDK additions made for the tools

| Area | Change |
|---|---|
| `sdk/libc/posixio.c` (new) | descriptor layer: `open creat close read write lseek unlink fstat stat isatty fcntl chmod getpid/uid/gid getcwd bcopy bzero bcmp` |
| `sdk/libc/stdio.c` | `fileno`, `fdopen`, `freopen` (a failed `freopen` of a standard stream falls back to the console), file-backed `stdout` writes through the descriptor; `fclose` rewrite |
| `sdk/libc/errno.c` | `sys_nerr`/`sys_errlist[39]` |
| `sdk/libc/{stdlib,malloc}.c`, `sdk/lib/{qdos,qdosfs}.c` | optional MEMSTAT hooks (compiled in only by `scripts/r11l-build-ms.sh`; never in identity runs) |
| kernel | `-DQDOS_FS_WRITE` writable FAT16 (see `R11L-FAT-WRITE-ABI.md`); `QDOS_APP_STACK` build option (64 KiB for R11L kernels); `shell-l` (160-char line) |
| `sdk/examples/r11l/` | `CC.AOU` (driver), `ENTER`, `DEL`, `REN`, `SUM` (CRC-32), `CMP`, `WRTTEST` |

## Defects found by running the real tools (kept as regression knowledge)

| Symptom | Cause | Fix |
|---|---|---|
| cccp triple-faulted on start | objects compiled against a 20-byte `struct stat`, libc wrote 28 bytes: `file_size_and_mode` returned into smashed stack | all tool objects rebuilt against `port/include/sys/stat.h` |
| cccp "I/O error on output" | no `freopen`/`write(fileno(stdout))` | implemented |
| GAS "Unknown error #2" | no `sys_errlist` | added |
| first guest `ld` run corrupted an existing `HELLO.AOU` | the 80-character shell line truncated the command | `shell-l` (160 chars) |
| tool links "succeeded" with missing symbols | stale `stub.o` files, and `ld` exiting 0 on "multiple definition" | stubs removed; link script treats any ld output as failure |
| paging kernel did not build | the first R11L traps collided with the R11K paging traps 0x25-0x29 | R11L traps moved to 0x2A-0x2C |
| `as` exits 0 when its input file is missing | historical behaviour | the driver verifies every output exists |

## Known differences from the host oracle

* The host-run `cc1` (LP64 repair) does not merge identical string literals; the guest `cc1` does. `.S` files of programs with
  repeated string constants therefore differ **only in the string pool**; `tools/r11l-sdiff.py` classifies this as
  "equivalent modulo the string pool". HELLO has one literal: all of its `.I .S .O .AOU` are byte-identical to the oracle.
* Exit status of cccp/cc1 on a fatal error is 33 (`FATAL_EXIT_CODE`), as on the host.
